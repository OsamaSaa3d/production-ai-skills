## Summary

Built a bug-triage **workflow** (not an autonomous agent — the four steps are fixed and always run in order, so I kept control flow in code per the agent-vs-workflow skill) in `bug_triage/`:

- **`models.py`** — Pydantic schemas for extraction, duplicate verdict, severity, routing, with a `needs_human_triage` abstention value for routing.
- **`llm.py`** — one call site using Claude's native structured output (`messages.parse(output_format=...)`), checking refusal/truncation before trusting the result.
- **`issue_store.py`** — pluggable issue tracker (JSON-backed, lexical scoring), swappable for a real tracker + vector search.
- **`routing.py`** — deterministic component→team dict lookup, LLM classification only as a fallback for unmatched components.
- **`triage.py`** — orchestrates extract → duplicate-check → severity → route, short-circuiting severity/routing when a high-confidence duplicate is found, and skipping the duplicate-judgment LLM call entirely when search finds no candidates.
- **`cli.py`** — run it end-to-end: `python -m bug_triage.cli "report text"`.
- **`tests/`** — offline tests via a `StubLLM` (no network/API key needed); all 3 pass.

README covers the architecture rationale, severity rubric, routing extension, and what's still needed before production (evals, real vector search, human review before auto-filing/closing tickets).

**Next step:** set `ANTHROPIC_API_KEY` and run it against a real report to see the full pipeline hit the actual model.

````py
"""Run triage on a single bug report from stdin, a file, or an inline arg.

Usage:
    python -m bug_triage.cli --file report.txt
    python -m bug_triage.cli "Users can't log in with SSO since this morning"
    echo "..." | python -m bug_triage.cli
"""

from __future__ import annotations

import argparse
import sys

from .issue_store import IssueStore
from .llm import AnthropicStructuredLLM
from .triage import triage_report


def main() -> None:
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("report", nargs="?", help="Bug report text (omit to read a --file or stdin)")
    parser.add_argument("--file", help="Path to a text file containing the bug report")
    parser.add_argument("--model", default="claude-sonnet-5")
    args = parser.parse_args()

    if args.file:
        raw_report = open(args.file, encoding="utf-8").read()
    elif args.report:
        raw_report = args.report
    else:
        raw_report = sys.stdin.read()

    if not raw_report.strip():
        parser.error("no report text provided")

    store = IssueStore.from_json_file()
    llm = AnthropicStructuredLLM(model=args.model)

    result = triage_report(raw_report, store=store, llm=llm)
    print(result.model_dump_json(indent=2))


if __name__ == "__main__":
    main()

````

````py
class TriageLLMError(Exception):
    """Base class for the two structured-output failure modes we must handle explicitly."""


class RefusalError(TriageLLMError):
    def __init__(self, stop_reason: str):
        super().__init__(f"Model declined to produce structured output (stop_reason={stop_reason!r})")
        self.stop_reason = stop_reason


class TruncatedOutputError(TriageLLMError):
    def __init__(self):
        super().__init__("Response hit max_tokens before completing the structured output; retry with a higher limit")


class EmptyOutputError(TriageLLMError):
    def __init__(self):
        super().__init__("stop_reason was clean but parsed_output was empty")

````

### `bug_triage/issue_store.py`

````py
"""A minimal issue tracker abstraction.

Ships with a JSON-backed store and lexical scoring so the whole pipeline runs
with zero external services. Swap `IssueStore.search` for a call to your real
tracker (Jira/Linear/GitHub Issues) plus a real embedding/vector search and
nothing else in the workflow needs to change — that's the point of keeping
this behind one small interface.
"""

from __future__ import annotations

import json
import re
from dataclasses import dataclass
from pathlib import Path

DEFAULT_DATA_PATH = Path(__file__).parent / "data" / "issues.json"

_TOKEN_RE = re.compile(r"[a-z0-9]+")


def _tokenize(text: str) -> set[str]:
    return set(_TOKEN_RE.findall(text.lower()))


@dataclass
class Issue:
    id: str
    title: str
    description: str
    component: str
    status: str  # "open" | "closed"


class IssueStore:
    def __init__(self, issues: list[Issue]):
        self._issues = issues

    @classmethod
    def from_json_file(cls, path: Path = DEFAULT_DATA_PATH) -> "IssueStore":
        raw = json.loads(path.read_text(encoding="utf-8"))
        return cls([Issue(**item) for item in raw])

    def all_open(self) -> list[Issue]:
        return [i for i in self._issues if i.status == "open"]

    def get(self, issue_id: str) -> Issue | None:
        return next((i for i in self._issues if i.id == issue_id), None)

    def search(self, query: str, *, component: str | None = None, top_k: int = 5) -> list[tuple[Issue, float]]:
        """Jaccard token overlap over open issues, optionally pre-filtered by component.

        Good enough to surface plausible duplicate candidates for the LLM to
        judge; not a substitute for real semantic/vector search at scale.
        """
        query_tokens = _tokenize(query)
        if not query_tokens:
            return []

        candidates = self.all_open()
        if component:
            same_component = [i for i in candidates if i.component == component]
            if same_component:
                candidates = same_component

        scored: list[tuple[Issue, float]] = []
        for issue in candidates:
            issue_tokens = _tokenize(f"{issue.title} {issue.description}")
            if not issue_tokens:
                continue
            overlap = len(query_tokens & issue_tokens)
            union = len(query_tokens | issue_tokens)
            score = overlap / union if union else 0.0
            if score > 0:
                scored.append((issue, score))

        scored.sort(key=lambda pair: pair[1], reverse=True)
        return scored[:top_k]

````

### `bug_triage/llm.py`

````py
"""Thin wrapper around Claude's structured-output feature.

One call site, one place that checks refusal/truncation. The rest of the
workflow only ever sees a typed Pydantic object back — no JSON parsing, no
markdown-fence stripping, no retry-on-malformed loop anywhere else in this
codebase.
"""

from __future__ import annotations

from typing import Protocol, TypeVar

from anthropic import Anthropic
from pydantic import BaseModel

from .errors import EmptyOutputError, RefusalError, TruncatedOutputError

ModelT = TypeVar("ModelT", bound=BaseModel)

DEFAULT_MODEL = "claude-sonnet-5"


class StructuredLLM(Protocol):
    """Everything the workflow needs from an LLM. Swap in a stub for tests."""

    def structured(self, *, system: str, user: str, schema: type[ModelT], max_tokens: int = 1024) -> ModelT: ...


class AnthropicStructuredLLM:
    def __init__(self, client: Anthropic | None = None, model: str = DEFAULT_MODEL):
        self._client = client or Anthropic()
        self._model = model

    def structured(self, *, system: str, user: str, schema: type[ModelT], max_tokens: int = 1024) -> ModelT:
        response = self._client.messages.parse(
            model=self._model,
            max_tokens=max_tokens,
            system=system,
            messages=[{"role": "user", "content": user}],
            output_format=schema,
        )

        # Strict mode guarantees conformance except for these two cases —
        # both must be checked before touching parsed_output.
        if response.stop_reason == "refusal":
            raise RefusalError(response.stop_reason)
        if response.stop_reason == "max_tokens":
            raise TruncatedOutputError()

        parsed = response.parsed_output
        if parsed is None:
            raise EmptyOutputError()
        return parsed

````

### `bug_triage/models.py`

````py
"""Pydantic schemas shared by every step of the triage workflow.

Regular Optional fields are fine here — the Anthropic SDK's `messages.parse()`
runs the schema through `transform_schema()` before sending it, which adds
`additionalProperties: false` and converts optional fields into the
nullable-but-required form strict mode needs. We don't have to hand-write that.
"""

from __future__ import annotations

from enum import Enum
from typing import Optional

from pydantic import BaseModel, Field


class Severity(str, Enum):
    CRITICAL = "critical"
    HIGH = "high"
    MEDIUM = "medium"
    LOW = "low"


class Team(str, Enum):
    AUTH = "auth"
    PAYMENTS = "payments"
    PLATFORM_API = "platform_api"
    FRONTEND = "frontend"
    MOBILE = "mobile"
    INFRA = "infra"
    DATA_ANALYTICS = "data_analytics"
    NOTIFICATIONS = "notifications"
    SEARCH = "search"
    BILLING = "billing"
    # Abstention value: routing couldn't confidently pick a team.
    NEEDS_HUMAN_TRIAGE = "needs_human_triage"


class ExtractedReport(BaseModel):
    """Structured facts pulled out of a free-text bug report."""

    title: str = Field(description="Short one-line summary of the bug, written from scratch if the report lacks one")
    component: Optional[str] = Field(
        default=None,
        description=(
            "Best-guess subsystem or feature area the bug lives in, e.g. 'checkout', "
            "'login', 'push-notifications'. Null if genuinely unclear from the report."
        ),
    )
    steps_to_reproduce: Optional[str] = Field(default=None, description="Reproduction steps, if the reporter gave any")
    expected_behavior: Optional[str] = None
    actual_behavior: Optional[str] = None
    affected_scope: Optional[str] = Field(
        default=None,
        description="Who/how many are affected, e.g. 'all users', 'single enterprise customer', 'iOS users only'",
    )
    has_workaround: Optional[bool] = Field(
        default=None, description="Whether the reporter mentioned a workaround exists"
    )
    environment: Optional[str] = Field(default=None, description="OS/browser/app version/environment, if mentioned")


class DuplicateVerdict(BaseModel):
    is_duplicate: bool
    duplicate_of: Optional[str] = Field(default=None, description="Issue ID of the matching existing issue, if any")
    confidence: float = Field(description="0.0-1.0 confidence in the duplicate judgment")
    reasoning: str = Field(description="One or two sentences explaining the judgment")


class SeverityVerdict(BaseModel):
    severity: Severity
    confidence: float = Field(description="0.0-1.0 confidence in the severity assignment")
    reasoning: str


class TeamClassification(BaseModel):
    """Used only for the LLM fallback path when the routing table can't decide."""

    team: Team
    reasoning: str


class RoutingVerdict(BaseModel):
    team: Team
    reasoning: str
    matched_rule: Optional[str] = Field(
        default=None, description="Routing-table keyword that matched, null if the LLM fallback decided instead"
    )


class DuplicateCandidate(BaseModel):
    issue_id: str
    title: str
    score: float


class TriageResult(BaseModel):
    extracted: ExtractedReport
    duplicate: DuplicateVerdict
    severity: Optional[SeverityVerdict] = Field(
        default=None, description="Null when the report was filed as a duplicate and severity wasn't (re)computed"
    )
    routing: Optional[RoutingVerdict] = None
    candidates_considered: list[DuplicateCandidate] = Field(default_factory=list)
    recommended_action: str

````

### `bug_triage/routing.py`

````py
"""Component -> team routing.

Deterministic table first, because the mapping is small, known in advance,
and a plain dict is cheaper and more auditable than a model call. The LLM is
only invoked as a fallback when the extracted component doesn't match any
known keyword — see `route()`.
"""

from __future__ import annotations

from .llm import StructuredLLM
from .models import ExtractedReport, RoutingVerdict, Team, TeamClassification

# Substring keywords (checked against the lowercased `component` field) mapped
# to the owning team. Extend this as your org's component taxonomy grows.
ROUTING_TABLE: dict[str, Team] = {
    "login": Team.AUTH,
    "auth": Team.AUTH,
    "signup": Team.AUTH,
    "password": Team.AUTH,
    "checkout": Team.PAYMENTS,
    "payment": Team.PAYMENTS,
    "gift-card": Team.PAYMENTS,
    "billing": Team.BILLING,
    "invoice": Team.BILLING,
    "subscription": Team.BILLING,
    "api": Team.PLATFORM_API,
    "webhook": Team.PLATFORM_API,
    "rate-limit": Team.PLATFORM_API,
    "frontend": Team.FRONTEND,
    "dashboard": Team.FRONTEND,
    "ui": Team.FRONTEND,
    "mobile": Team.MOBILE,
    "ios": Team.MOBILE,
    "android": Team.MOBILE,
    "infra": Team.INFRA,
    "deploy": Team.INFRA,
    "outage": Team.INFRA,
    "analytics": Team.DATA_ANALYTICS,
    "reporting": Team.DATA_ANALYTICS,
    "notification": Team.NOTIFICATIONS,
    "email": Team.NOTIFICATIONS,
    "push": Team.NOTIFICATIONS,
    "search": Team.SEARCH,
}


def route(report: ExtractedReport, llm: StructuredLLM) -> RoutingVerdict:
    component = (report.component or "").lower()

    for keyword, team in ROUTING_TABLE.items():
        if keyword in component:
            return RoutingVerdict(
                team=team,
                reasoning=f"Component '{report.component}' matched routing keyword '{keyword}'.",
                matched_rule=keyword,
            )

    # No keyword matched — component was missing, unrecognized, or too vague.
    # Fall back to a bounded classification call rather than guessing in code.
    classification = llm.structured(
        system=(
            "You route bug reports to engineering teams. Choose the single best team "
            "from the enum. If nothing fits confidently, choose needs_human_triage — "
            "do not force a guess."
        ),
        user=(
            f"Title: {report.title}\n"
            f"Component (as reported): {report.component or 'unknown'}\n"
            f"Actual behavior: {report.actual_behavior or 'n/a'}\n"
            f"Affected scope: {report.affected_scope or 'n/a'}"
        ),
        schema=TeamClassification,
    )
    return RoutingVerdict(
        team=classification.team,
        reasoning=classification.reasoning,
        matched_rule=None,
    )
````

### `bug_triage/tests/test_triage.py`

````py
"""Tests run entirely offline: a StubLLM replaces the Anthropic call so the
deterministic parts of the workflow (issue search, routing table, control
flow, recommended_action wording) are covered without a network or API key.
"""

from __future__ import annotations

from pydantic import BaseModel

from bug_triage.issue_store import Issue, IssueStore
from bug_triage.models import (
    DuplicateVerdict,
    ExtractedReport,
    RoutingVerdict,
    Severity,
    SeverityVerdict,
    Team,
    TeamClassification,
)
from bug_triage.triage import triage_report


class StubLLM:
    """Returns pre-built responses in call order. Verifies the requested
    schema matches what the test queued, so a workflow change that adds or
    reorders a call fails loudly here instead of returning nonsense."""

    def __init__(self, responses: list[BaseModel]):
        self._responses = list(responses)
        self.calls: list[type[BaseModel]] = []

    def structured(self, *, system: str, user: str, schema, max_tokens: int = 1024):
        self.calls.append(schema)
        assert self._responses, f"StubLLM ran out of responses (requested {schema.__name__})"
        response = self._responses.pop(0)
        assert isinstance(response, schema), f"expected {schema.__name__}, queued {type(response).__name__}"
        return response


def make_store(*issues: Issue) -> IssueStore:
    return IssueStore(list(issues))


def test_high_confidence_duplicate_skips_severity_and_routing():
    store = make_store(
        Issue(
            id="BUG-101",
            title="Checkout fails with 500 error when applying a gift card",
            description="Users hit a server error applying a gift card at checkout.",
            component="checkout",
            status="open",
        )
    )
    llm = StubLLM(
        [
            ExtractedReport(
                title="Gift card breaks checkout",
                component="checkout",
                actual_behavior="500 error when applying a gift card at checkout",
                steps_to_reproduce="Add item, enter gift card code, click Apply",
            ),
            DuplicateVerdict(
                is_duplicate=True,
                duplicate_of="BUG-101",
                confidence=0.95,
                reasoning="Same gift-card-at-checkout 500 error.",
            ),
        ]
    )

    result = triage_report("checkout is broken with gift cards", store=store, llm=llm)

    assert result.duplicate.is_duplicate is True
    assert result.severity is None
    assert result.routing is None
    assert "BUG-101" in result.recommended_action
    assert llm.calls == [ExtractedReport, DuplicateVerdict]


def test_novel_report_routes_via_table_without_extra_llm_call():
    store = make_store()  # empty store -> duplicate search short-circuits, no LLM call for it
    llm = StubLLM(
        [
            ExtractedReport(
                title="SSO login fails for all users",
                component="login",
                actual_behavior="SSO redirect loops back to the login page",
                affected_scope="all users",
            ),
            SeverityVerdict(severity=Severity.CRITICAL, confidence=0.9, reasoning="Full outage, no workaround."),
        ]
    )

    result = triage_report("nobody can log in via SSO this morning", store=store, llm=llm)

    assert result.duplicate.is_duplicate is False
    assert result.severity.severity == Severity.CRITICAL
    assert result.routing.team == Team.AUTH
    assert result.routing.matched_rule == "login"
    assert "CRITICAL" in result.recommended_action
    assert "auth" in result.recommended_action
    # routing came from the table, so no TeamClassification call was made
    assert llm.calls == [ExtractedReport, SeverityVerdict]


def test_unrecognized_component_falls_back_to_llm_routing():
    store = make_store()
    llm = StubLLM(
        [
            ExtractedReport(
                title="Onboarding survey widget throws a blank screen",
                component="onboarding-survey-widget",
                actual_behavior="Blank white screen after step 2 of the new-user survey",
                affected_scope="new signups only",
            ),
            SeverityVerdict(severity=Severity.MEDIUM, confidence=0.6, reasoning="Narrow scope, no data loss."),
            TeamClassification(team=Team.FRONTEND, reasoning="Rendering bug in a UI widget."),
        ]
    )

    result = triage_report("the new survey thing shows a blank screen", store=store, llm=llm)

    assert result.routing.team == Team.FRONTEND
    assert result.routing.matched_rule is None
    assert llm.calls == [ExtractedReport, SeverityVerdict, TeamClassification]
````

### `bug_triage/triage.py`

````py
"""The triage workflow.

This is deliberately a workflow, not an autonomous agent: the four steps
(extract -> check duplicates -> classify severity -> route) are fixed, their
order never varies, and the count doesn't depend on anything discovered
mid-run. Control flow lives here in code; the LLM is called for judgment
within each step, never to decide what step comes next. See the project
README for the "why not an agent" reasoning.

Duplicate search is done by the *program* calling `IssueStore.search`
directly, not by handing the model a search tool and letting it decide when
to call it — the step always runs, so there is nothing for a tool-calling
loop to add here.
"""

from __future__ import annotations

from .issue_store import IssueStore
from .llm import StructuredLLM
from .models import (
    DuplicateCandidate,
    DuplicateVerdict,
    ExtractedReport,
    SeverityVerdict,
    TriageResult,
)
from .routing import route

DUPLICATE_CONFIDENCE_THRESHOLD = 0.7

EXTRACTION_SYSTEM_PROMPT = """\
You extract structured facts from a raw, possibly messy bug report (which may \
be a support ticket, Slack message, or email forward). Only use information \
present in the text. Leave a field null rather than inventing a plausible-\
sounding value when the report doesn't say."""

SEVERITY_SYSTEM_PROMPT = """\
You assign a severity label to a bug report using this rubric:

- critical: data loss/corruption, security vulnerability, or a full outage; \
no workaround.
- high: a major feature is broken for a large share of users; no reasonable \
workaround, or only a painful one.
- medium: a feature is partially broken or broken for a narrow subset of \
users; a workaround exists.
- low: cosmetic, minor, or edge-case behavior with negligible user impact.

Base the label only on the report's content, not on how urgently it's worded."""


def _duplicate_search_query(report: ExtractedReport) -> str:
    parts = [report.title, report.actual_behavior or "", report.steps_to_reproduce or ""]
    return " ".join(p for p in parts if p)


def _check_duplicate(
    report: ExtractedReport, store: IssueStore, llm: StructuredLLM
) -> tuple[DuplicateVerdict, list[DuplicateCandidate]]:
    query = _duplicate_search_query(report)
    hits = store.search(query, component=report.component, top_k=5)

    if not hits:
        return (
            DuplicateVerdict(
                is_duplicate=False,
                duplicate_of=None,
                confidence=1.0,
                reasoning="No open issues shared any meaningful text overlap with this report.",
            ),
            [],
        )

    candidates = [DuplicateCandidate(issue_id=i.id, title=i.title, score=score) for i, score in hits]
    candidate_block = "\n".join(
        f"- {i.id}: {i.title}\n  {i.description}" for i, _score in hits
    )
    verdict = llm.structured(
        system=(
            "You decide whether a new bug report is a duplicate of an existing open issue. "
            "Only mark it a duplicate if it describes the same underlying bug, not just a "
            "similar area of the product. When unsure, prefer is_duplicate=false with a lower "
            "confidence rather than guessing."
        ),
        user=(
            f"New report:\nTitle: {report.title}\n"
            f"Actual behavior: {report.actual_behavior or 'n/a'}\n"
            f"Steps to reproduce: {report.steps_to_reproduce or 'n/a'}\n\n"
            f"Candidate existing open issues:\n{candidate_block}"
        ),
        schema=DuplicateVerdict,
    )
    return verdict, candidates


def _classify_severity(report: ExtractedReport, llm: StructuredLLM) -> SeverityVerdict:
    return llm.structured(
        system=SEVERITY_SYSTEM_PROMPT,
        user=(
            f"Title: {report.title}\n"
            f"Actual behavior: {report.actual_behavior or 'n/a'}\n"
            f"Expected behavior: {report.expected_behavior or 'n/a'}\n"
            f"Affected scope: {report.affected_scope or 'n/a'}\n"
            f"Workaround available: {report.has_workaround}"
        ),
        schema=SeverityVerdict,
    )


def triage_report(raw_report: str, *, store: IssueStore, llm: StructuredLLM) -> TriageResult:
    extracted = llm.structured(
        system=EXTRACTION_SYSTEM_PROMPT,
        user=raw_report,
        schema=ExtractedReport,
    )

    duplicate, candidates = _check_duplicate(extracted, store, llm)

    if duplicate.is_duplicate and duplicate.confidence >= DUPLICATE_CONFIDENCE_THRESHOLD:
        return TriageResult(
            extracted=extracted,
            duplicate=duplicate,
            severity=None,
            routing=None,
            candidates_considered=candidates,
            recommended_action=(
                f"Link as duplicate of {duplicate.duplicate_of} and close without filing a new ticket."
            ),
        )

    severity = _classify_severity(extracted, llm)
    routing = route(extracted, llm)

    return TriageResult(
        extracted=extracted,
        duplicate=duplicate,
        severity=severity,
        routing=routing,
        candidates_considered=candidates,
        recommended_action=(
            f"File as a new {severity.severity.value.upper()} severity ticket and route to "
            f"the {routing.team.value} team."
        ),
    )

````

### `README.md`

````md
# Bug report triage

Takes a raw bug report and produces: extracted structured fields, a
duplicate-of-existing-issue verdict, a severity label, and a team assignment.

## Why this is a workflow, not an agent

The four steps — extract, check duplicates, classify severity, route — are
fixed, always run in this order, and the step count never depends on
anything discovered mid-run. There's no case where the "right" next step is
unknowable in advance, which is the actual test for whether autonomy earns
its cost. So the control flow lives in plain code (`triage.py`), and the LLM
is called for judgment *within* a step, never to decide what step runs next.
This also makes the pipeline cheaper, fully traceable, and unit-testable
without a network call (see `bug_triage/tests/`).

Two cost/reliability shortcuts fall out of keeping this a workflow:

- Duplicate search runs unconditionally as a plain function call
  (`IssueStore.search`) rather than being offered to the model as a tool it
  might decide to invoke — the step always runs, so a decision point would
  add latency and failure modes for nothing.
- If the search returns no candidates, or a high-confidence duplicate is
  found, later steps (LLM duplicate judgment, severity, routing) are skipped
  outright rather than run and discarded.

## Pipeline

```
raw text
  -> extract()          structured output: ExtractedReport
  -> IssueStore.search() plain code: lexical candidate search (swap for vector search)
  -> duplicate judgment  structured output: DuplicateVerdict   (skipped if no candidates)
       |
       +-- high-confidence duplicate --> done, no new ticket
       |
       v
  -> severity            structured output: SeverityVerdict
  -> route()              dict lookup first; structured output only as fallback
  -> TriageResult
```

All LLM calls go through `bug_triage/llm.py`, which uses Claude's native
structured-output feature (`messages.parse(..., output_format=SomeModel)`)
instead of prompting for JSON and parsing it — no fence-stripping, no
retry-on-malformed loop. That one call site is also the only place that
checks the two failure modes strict mode doesn't cover: refusal
(`stop_reason == "refusal"`) and truncation (`stop_reason == "max_tokens"`).

## Severity rubric

- **critical** — data loss/corruption, security vulnerability, or full
  outage; no workaround.
- **high** — a major feature broken for a large share of users; no
  reasonable workaround.
- **medium** — feature partially broken or affects a narrow subset; a
  workaround exists.
- **low** — cosmetic or negligible-impact edge case.

Edit `SEVERITY_SYSTEM_PROMPT` in `triage.py` to tune this for your product.

## Routing

`routing.py` has a `ROUTING_TABLE` dict of component keyword -> team. This is
deliberately not an LLM call: the mapping is small, known in advance, and a
dict is cheaper and easier to audit than a model decision. The LLM is only
invoked (as `TeamClassification`, one of the enum values plus
`needs_human_triage` as an explicit abstention option) when the extracted
component doesn't match any keyword — extend the table first if you find
reports landing in the fallback often.

## Swapping in a real issue tracker

`IssueStore` (`issue_store.py`) is the only thing that knows about issue
storage. The bundled version is a JSON file plus token-overlap scoring, so
the whole thing runs with zero external services. To go to production,
replace `IssueStore.search` with a call to your tracker's API (Jira, Linear,
GitHub Issues) backed by real embedding/vector search — nothing in
`triage.py` needs to change, since it only calls `store.search(...)`.

## Running it

```
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...   # PowerShell: $env:ANTHROPIC_API_KEY = "..."

python -m bug_triage.cli "Users can't log in with SSO since this morning, they get redirected back to the login page in a loop"
```

Or from a file: `python -m bug_triage.cli --file report.txt`.

Output is the `TriageResult` as JSON: extracted fields, duplicate verdict,
severity (null if short-circuited as a duplicate), routing, and a
`recommended_action` string assembled in code from the other fields.

## Tests

```
pip install pytest
pytest bug_triage/tests
```

Tests use a `StubLLM` that returns pre-built Pydantic objects in call order
and asserts the requested schema matches what was queued — so a workflow
change that adds, removes, or reorders an LLM call fails the test instead of
silently returning nonsense. No network or API key required.

## What's missing before production

This is a working pipeline, not a finished product. Before relying on it:

- **Evals.** Structured output guarantees shape, not correctness. Build a
  labelled set of real reports with known severity/team/duplicate-or-not and
  measure accuracy per field before trusting this on live traffic.
- **Real duplicate search.** Token overlap is a placeholder; use embeddings
  or your tracker's native search for anything beyond a demo.
- **Human-in-the-loop for high-stakes actions.** This pipeline only
  *recommends* an action (`recommended_action`); actually filing, closing,
  or linking tickets against your tracker's API should stay a deliberate,
  reviewable step, at least until the evals justify full automation.
````
