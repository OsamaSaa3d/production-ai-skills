That's the exact failure this skill documents: an `include`/`exclude` mode flag is an inverting polarity parameter — a wrong value is structurally valid, so it never errors, it just silently returns the opposite set. The fix is to move the polarity out of the parameter and into the tool name, giving the agent two tools with identical remaining schemas:

```python
{
    "name": "filter_records_including_value",
    "description": "Return only records where <field> equals <value>.",
    "input_schema": {
        "type": "object",
        "properties": {
            "field": {"type": "string", "description": "Field name to match on"},
            "value": {"type": "string", "description": "Value the field must equal"},
        },
        "required": ["field", "value"],
        "additionalProperties": false,
    },
},
{
    "name": "filter_records_excluding_value",
    "description": "Return all records except those where <field> equals <value>.",
    "input_schema": {
        "type": "object",
        "properties": {
            "field": {"type": "string", "description": "Field name to match on"},
            "value": {"type": "string", "description": "Value the field must equal"},
        },
        "required": ["field", "value"],
        "additionalProperties": false,
    },
}
```

On the implementation side, both dispatch to the same underlying filter function, just with `mode` fixed by which tool was called instead of passed by the model:

```python
def filter_records_including_value(field, value):
    return _filter_records(field, value, mode="include")

def filter_records_excluding_value(field, value):
    return _filter_records(field, value, mode="exclude")
```
