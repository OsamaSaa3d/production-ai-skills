Validation works as intended: legitimate `orders` queries pass (with a `LIMIT` auto-appended), while multi-statement injection, writes, joins to other tables, and CTE indirection are all rejected. The CTE case fails closed (rejected rather than allowed) — stricter than necessary but safe, worth knowing if you write CTE-heavy questions later.

## What I built: `orders_qa.py`

- **Loop**: Claude (via Anthropic tool calling, `strict: true`) receives the question, writes SQL, calls `query_orders`; the result comes back as a `tool_result` and Claude produces the plain-English answer. Standard single-tool agent loop, capped at 5 iterations.
- **SQL safety** (defense in depth, since letting a model emit arbitrary SQL is otherwise a textbook injection vector):
  - `sqlglot` parses the query and rejects anything that isn't exactly one `SELECT`
  - Table whitelist restricts it to `orders` only
  - Semicolons/multi-statements rejected before parsing
  - A `LIMIT 200` is force-appended if missing
  - The Postgres session is opened with `readonly=True` and a 5s `statement_timeout`
  - Rejections are returned to Claude as `is_error` tool results so it can retry with a valid query instead of the run just failing

**Setup** (in the file's docstring): `pip install anthropic psycopg2-binary sqlglot`, set `ANTHROPIC_API_KEY` and `ORDERS_DB_DSN`. I could only compile- and logic-test this (no live DB/API key here) — the SQL validator is verified above, but you should smoke-test an actual question against a real Postgres instance before trusting it in production.

One assumption worth flagging: `ORDERS_DB_DSN` should point at a Postgres role with `SELECT`-only grant on `orders` — the script's own validation is a second layer, not a substitute for that grant.

"""
Ask plain-English questions about the `orders` table and get answers.

Claude decides what SQL to run, calls the `query_orders` tool, and turns
the result into a plain-English answer. The tool only ever executes a
single, validated, read-only SELECT against the `orders` table -- Claude
never gets a raw connection, and free-text SQL from the model is treated
as untrusted input the same way user input would be.

Setup
-----
    pip install anthropic psycopg2-binary sqlglot

    export ANTHROPIC_API_KEY=...
    export ORDERS_DB_DSN="postgresql://orders_readonly:password@host:5432/dbname"

`ORDERS_DB_DSN` should point to a Postgres role that only has SELECT on
`orders` (e.g. `GRANT SELECT ON orders TO orders_readonly;`, no other
grants). The validation below is defense in depth, not a substitute for
that grant -- a bug in the parser should not be the only thing standing
between a question and a dropped table.

Usage
-----
    python orders_qa.py
    > how many orders were placed last week?
    > what's the average order total for cancelled orders?
"""

import json
import os

import anthropic
import psycopg2
import psycopg2.extras
import sqlglot
from sqlglot import exp

MODEL = "claude-sonnet-5"
MAX_ITERATIONS = 5
MAX_ROWS = 200
STATEMENT_TIMEOUT_MS = 5000

ALLOWED_TABLE = "orders"

SCHEMA_DESCRIPTION = """\
Table: orders
  id             integer, primary key
  customer_email text
  status         text (e.g. 'placed', 'shipped', 'delivered', 'cancelled', 'refunded')
  total_usd      numeric, order total in US dollars
  placed_at      timestamp, when the order was placed
"""

TOOLS = [
    {
        "name": "query_orders",
        "description": (
            "Run a read-only SQL SELECT query against the `orders` table to "
            "answer a question about customer orders. Only a single SELECT "
            "statement is accepted, and it must reference only the `orders` "
            "table -- no writes, no other tables, no multiple statements. "
            f"Returns up to {MAX_ROWS} rows as JSON. Prefer aggregating in "
            "SQL (COUNT, SUM, AVG, GROUP BY) over pulling raw rows. Do not "
            "use this tool to attempt any data modification -- it will "
            "reject the query and cannot alter data regardless."
        ),
        "strict": True,
        "input_schema": {
            "type": "object",
            "properties": {
                "sql": {
                    "type": "string",
                    "description": (
                        "A single PostgreSQL SELECT statement over the "
                        "orders table, e.g. 'SELECT status, COUNT(*) FROM "
                        "orders GROUP BY status'. No trailing semicolon, no "
                        "other statements."
                    ),
                }
            },
            "required": ["sql"],
            "additionalProperties": False,
        },
    }
]

SYSTEM_PROMPT = f"""\
You answer plain-English questions about a Postgres `orders` table by \
writing SQL and calling the query_orders tool. Never guess at data -- \
always query for it, and never fabricate rows or numbers.

{SCHEMA_DESCRIPTION}

Guidelines:
- Write standard PostgreSQL SELECT statements only.
- Prefer aggregating in SQL (COUNT, SUM, AVG, GROUP BY) over pulling raw \
rows and computing by hand.
- If a question is ambiguous (e.g. "recent" orders), pick a reasonable \
interpretation and state what you assumed.
- If the tool rejects a query, rewrite it to satisfy the restriction \
rather than giving up.
- Answer in plain English. Don't dump raw query results as a table \
unless the user asked for a list.
"""


class UnsafeQueryError(ValueError):
    """Raised when a model-generated query fails validation."""


def validate_select_only(sql: str) -> str:
    """Parse `sql` and enforce: single statement, SELECT only, `orders` only.

    Returns the query with a row limit applied, ready to execute. Raises
    UnsafeQueryError with a message the model can act on and retry from.
    """
    cleaned = sql.strip()
    if cleaned.endswith(";"):
        cleaned = cleaned[:-1].strip()
    if ";" in cleaned:
        raise UnsafeQueryError("Only a single statement is allowed (no semicolons).")

    try:
        statements = [s for s in sqlglot.parse(cleaned, read="postgres") if s is not None]
    except Exception as e:
        raise UnsafeQueryError(f"Could not parse SQL: {e}")

    if len(statements) != 1:
        raise UnsafeQueryError("Only a single SELECT statement is allowed.")

    stmt = statements[0]
    if not isinstance(stmt, exp.Select):
        raise UnsafeQueryError("Only SELECT statements are allowed.")

    tables = {t.name.lower() for t in stmt.find_all(exp.Table)}
    disallowed = tables - {ALLOWED_TABLE}
    if disallowed:
        raise UnsafeQueryError(
            f"Query references disallowed table(s): {sorted(disallowed)}. "
            f"Only '{ALLOWED_TABLE}' is available."
        )

    if not stmt.args.get("limit"):
        stmt = stmt.limit(MAX_ROWS)

    return stmt.sql(dialect="postgres")


def query_orders(sql: str) -> dict:
    safe_sql = validate_select_only(sql)

    conn = psycopg2.connect(os.environ["ORDERS_DB_DSN"])
    conn.set_session(readonly=True, autocommit=False)
    try:
        with conn:
            with conn.cursor(cursor_factory=psycopg2.extras.RealDictCursor) as cur:
                # STATEMENT_TIMEOUT_MS is a fixed internal constant, not
                # user input, so building it into the SQL text is safe.
                cur.execute(f"SET LOCAL statement_timeout = {STATEMENT_TIMEOUT_MS}")
                cur.execute(safe_sql)
                rows = cur.fetchmany(MAX_ROWS)
    finally:
        conn.close()

    return {
        "row_count": len(rows),
        "rows": [dict(row) for row in rows],
    }


TOOL_REGISTRY = {"query_orders": query_orders}


def ask(question: str, client: anthropic.Anthropic) -> str:
    messages = [{"role": "user", "content": question}]

    for _ in range(MAX_ITERATIONS):
        response = client.messages.create(
            model=MODEL,
            max_tokens=2048,
            system=SYSTEM_PROMPT,
            tools=TOOLS,
            messages=messages,
        )

        if response.stop_reason == "refusal":
            return "I can't help with that request."

        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason != "tool_use":
            return "".join(b.text for b in response.content if b.type == "text")

        results = []
        for block in response.content:
            if block.type != "tool_use":
                continue
            try:
                output = TOOL_REGISTRY[block.name](**block.input)
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": json.dumps(output, default=str),
                })
            except UnsafeQueryError as e:
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": (
                        f"Query rejected: {e} Rewrite it as a single "
                        "read-only SELECT over the orders table."
                    ),
                    "is_error": True,
                })
            except Exception as e:
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": f"{type(e).__name__}: {e}",
                    "is_error": True,
                })

        messages.append({"role": "user", "content": results})

    return "I couldn't find an answer within the allotted number of steps."


def main():
    client = anthropic.Anthropic()
    print("Ask questions about customer orders in plain English (Ctrl+C to quit).")
    while True:
        try:
            question = input("\n> ").strip()
        except (EOFError, KeyboardInterrupt):
            print()
            break
        if not question:
            continue
        print(ask(question, client))


if __name__ == "__main__":
    main()
