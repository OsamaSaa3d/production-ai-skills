**How it works:**
- **Two tools**, defined as plain typed functions via `@beta_tool` (schema is auto-generated from the signature + docstring):
  - `lookup_order(order_id)` — returns status, total, and how much has already been refunded.
  - `issue_refund(order_id, amount, reason)` — validates the order exists and the amount doesn't exceed what's actually refundable, then **pauses for a human `y/N` confirmation** before touching the mock "database". Refunds are real, hard-to-reverse actions, so I gated it rather than letting the model fire it unsupervised — swap that `input()` for your real approval/paging flow and add an idempotency key in production.
- **Outer `while` loop** is the multi-turn conversation (one user message per iteration). Inside each turn, `client.beta.messages.tool_runner(...)` drives the *tool-call* loop: Claude looks up the order, gets the result fed back automatically, decides whether to call the refund tool, etc., until it has a final answer for that turn.
- Since the tool runner doesn't expose its internal history, I mirror it manually each iteration (`messages.append(...)` for both the assistant turn and `runner.generate_tool_call_response()`) so the *next* user turn is seeded with the full true transcript, including past tool calls/results — same pattern the SDK docs use for resuming a `pause_turn`.
- System prompt tells the model to always look up the order before refunding (never trust a customer-stated amount) and to confirm details with the customer first.
- Basic error handling for rate limits / API errors / connection errors around each turn.

Model is `claude-opus-5` per this skill's default. Run with `pip install anthropic` and `ANTHROPIC_API_KEY` set (or `ant auth login`), then `python support_bot.py`.

"""
Support bot: looks up orders and issues refunds via Claude tool use.

Uses the beta tool runner (client.beta.messages.tool_runner) to drive the
agentic loop for you - Claude decides when to call lookup_order / issue_refund,
the runner executes them and feeds results back, and it stops automatically
once Claude has a final answer for the turn. The outer while-loop is the
*conversation* loop (one iteration per user message); the runner handles the
*tool-call* loop within each turn.

Since the runner doesn't expose its internal message history, we mirror it
ourselves as we iterate (same pattern used to recover from pause_turn) so the
next conversation turn is fed the true history, including tool calls/results.
"""

import anthropic
from anthropic import beta_tool

client = anthropic.Anthropic()

# --- Mock "database" -------------------------------------------------------

ORDERS = {
    "ORD-1001": {
        "customer": "Jane Doe",
        "status": "delivered",
        "total": 89.99,
        "refunded": 0.0,
        "items": ["Wireless Mouse", "USB-C Hub"],
    },
    "ORD-1002": {
        "customer": "John Smith",
        "status": "delivered",
        "total": 42.50,
        "refunded": 42.50,  # already fully refunded
        "items": ["Notebook Set"],
    },
}


# --- Tools -------------------------------------------------------------

@beta_tool
def lookup_order(order_id: str) -> str:
    """Look up an order by ID and return its status, total, refund history, and items.

    Args:
        order_id: The order identifier, e.g. "ORD-1001".
    """
    order = ORDERS.get(order_id)
    if order is None:
        return f"No order found with ID '{order_id}'."
    return (
        f"Order {order_id}: customer={order['customer']}, status={order['status']}, "
        f"total=${order['total']:.2f}, already refunded=${order['refunded']:.2f}, "
        f"items={order['items']}"
    )


@beta_tool
def issue_refund(order_id: str, amount: float, reason: str) -> str:
    """Issue a refund for an order after validating it. Requires human confirmation
    before the refund is actually processed, since it's a real, hard-to-reverse action.

    Args:
        order_id: The order identifier, e.g. "ORD-1001".
        amount: Amount to refund in USD. Must not exceed the order total minus
            any amount already refunded.
        reason: Why the refund is being issued, e.g. "damaged item".
    """
    order = ORDERS.get(order_id)
    if order is None:
        return f"Cannot refund: no order found with ID '{order_id}'."

    remaining = order["total"] - order["refunded"]
    if amount <= 0:
        return "Cannot refund: amount must be greater than $0."
    if amount > remaining:
        return (
            f"Cannot refund ${amount:.2f}: only ${remaining:.2f} is refundable "
            f"on order {order_id} (total ${order['total']:.2f}, "
            f"already refunded ${order['refunded']:.2f})."
        )

    # Human-in-the-loop gate: refunds are real money movement, so a person
    # confirms before we touch the "database". Swap this for your real
    # approval/paging flow (and an idempotency key) in production.
    print(
        f"\n[CONFIRM] Refund ${amount:.2f} on {order_id} "
        f"({order['customer']}) - reason: {reason}"
    )
    approved = input("Approve this refund? [y/N] ").strip().lower() == "y"
    if not approved:
        return "Refund declined by support agent. Do not retry without new approval."

    order["refunded"] += amount
    return f"Refunded ${amount:.2f} on order {order_id}. New refunded total: ${order['refunded']:.2f}."


TOOLS = [lookup_order, issue_refund]

SYSTEM_PROMPT = """You are a customer support assistant for an online store.
You can look up orders and issue refunds using the tools provided.

Rules:
- Always look up the order before issuing a refund, so you know the real total
  and refund history - never take the customer's word for the amount owed.
- Confirm the order details and refund amount with the customer before calling
  issue_refund.
- Never refund more than what lookup_order reports as remaining.
- If a tool reports an error (order not found, already refunded, declined),
  explain it plainly to the customer instead of retrying blindly.
- Be concise and friendly.
"""


def main() -> None:
    messages: list[dict] = []
    print("Support bot ready. Type 'exit' to quit.\n")

    while True:
        user_input = input("You: ").strip()
        if user_input.lower() in ("exit", "quit"):
            break
        if not user_input:
            continue

        messages.append({"role": "user", "content": user_input})

        try:
            runner = client.beta.messages.tool_runner(
                model="claude-opus-5",
                max_tokens=16000,
                system=SYSTEM_PROMPT,
                tools=TOOLS,
                messages=messages,
            )

            last_text = None
            for message in runner:
                # Mirror the runner's history ourselves - it doesn't expose it,
                # and we need the full transcript (including tool_use/tool_result)
                # to seed the next conversation turn.
                messages.append({"role": "assistant", "content": message.content})
                tool_response = runner.generate_tool_call_response()
                if tool_response is not None:
                    messages.append(tool_response)

                text = next((b.text for b in message.content if b.type == "text"), None)
                if text:
                    last_text = text

            print(f"Bot: {last_text}\n")

        except anthropic.RateLimitError as e:
            retry_after = e.response.headers.get("retry-after", "a few")
            print(f"[rate limited, retry after {retry_after}s]\n")
        except anthropic.APIStatusError as e:
            print(f"[API error {e.status_code}: {e.message}]\n")
        except anthropic.APIConnectionError:
            print("[network error - check your connection]\n")


if __name__ == "__main__":
    main()
