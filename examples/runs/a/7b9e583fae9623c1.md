Wrote `support_bot.py` — a runnable multi-turn support bot with two tools, `lookup_order` and `issue_refund`, over Claude Opus 5.

**Assumption:** the directory was empty, so I picked Python + the official `anthropic` SDK. Say the word if you actually want TypeScript/Go/etc.

How it's structured:

- **Two loops.** The outer `while True` in `main()` is the conversation — one user message per iteration. The inner loop in `run_agent_turn()` is the tool-use round-trip within a single turn: Claude can call `lookup_order`, see the result, then call `issue_refund`, then reply in text, all before control returns to the user.
- **Manual loop, not the beta tool runner** — deliberate, so the refund path (validation, human-approval gate, tool_result wiring) stays fully explicit and auditable rather than hidden inside a decorator, and it avoids a beta SDK dependency for a financial action.
- **`lookup_order`** returns items/total/status/refunded amount from a mock in-memory `ORDERS` dict — swap in your real order-service call.
- **`issue_refund`** validates the order exists, amount > 0, and amount doesn't exceed the refundable balance, then calls `request_human_approval(...)` **before** mutating anything. Refunds are hard to reverse, so nothing actually happens until that gate returns true — right now it's a stdin `y/N` prompt as a stand-in; wire it to your real approval queue/Slack-button/supervisor flow.
- Tool schemas use `strict: true` with `additionalProperties: false` so inputs are always schema-valid.
- Tool failures (`ToolError`) come back as `is_error: true` tool_results instead of raising, so Claude can explain the problem to the customer instead of the process crashing.
- Errors from the API itself are handled as a most-specific-first chain (`RateLimitError` → `APIConnectionError` → `APIStatusError`, retrying 5xx, raising 4xx) rather than one broad `except`.

Try it (after `pip install anthropic` and auth): `python support_bot.py`, then something like "I want a refund for ORD-1001, the headphones arrived broken" — it'll look the order up, ask you to confirm amount/reason, then prompt for approval in the terminal before "issuing" the refund.

"""
Support bot: multi-turn agentic loop with order lookup + refund tools.

Assumptions (no project/language was detected in this empty directory):
  - Python, using the official `anthropic` SDK (`pip install anthropic`).
  - `ANTHROPIC_API_KEY` (or an `ant auth login` profile) is set in the environment.
  - Order/refund backend is mocked in-memory - swap `ORDERS` and the two functions
    below for real calls to your order-management / payments system.

Design notes:
  - This is a *manual* agentic loop (not the beta tool runner) so the refund path
    can be made fully explicit and auditable - each tool call, its result, and the
    human-approval gate are all visible in the loop rather than hidden in a helper.
  - Refunds are hard to reverse, so `issue_refund` requires a human-approval step
    before it mutates anything. Replace `request_human_approval` with your real
    approval workflow (a queue, a Slack button, a supervisor UI) - the stdin
    prompt here is a stand-in for that gate, not a suggestion to ship it as-is.
  - The outer `while True` loop is the multi-turn *conversation* (one user message
    at a time); the inner loop inside `run_agent_turn` is the multi-round *tool use*
    within a single turn (Claude may call lookup_order, see the result, then call
    issue_refund, before finally replying in text).
"""

import json
import time
import uuid

import anthropic

MODEL = "claude-opus-5"

client = anthropic.Anthropic()

# --------------------------------------------------------------------------
# Mock backend - replace with real order-lookup / payment-processor calls.
# --------------------------------------------------------------------------

ORDERS = {
    "ORD-1001": {
        "customer_email": "alice@example.com",
        "items": ["Wireless Headphones"],
        "total": 129.99,
        "currency": "USD",
        "status": "delivered",
        "refunded_amount": 0.0,
    },
    "ORD-1002": {
        "customer_email": "bob@example.com",
        "items": ["Desk Lamp", "USB Cable"],
        "total": 42.50,
        "currency": "USD",
        "status": "delivered",
        "refunded_amount": 42.50,  # already fully refunded
    },
}


class ToolError(Exception):
    """Raised for tool-level failures that should be sent back to Claude as is_error results."""


def lookup_order(order_id: str) -> dict:
    order = ORDERS.get(order_id)
    if order is None:
        raise ToolError(f"No order found with id '{order_id}'.")
    return {
        "order_id": order_id,
        "customer_email": order["customer_email"],
        "items": order["items"],
        "total": order["total"],
        "currency": order["currency"],
        "status": order["status"],
        "refunded_amount": order["refunded_amount"],
        "refundable_balance": round(order["total"] - order["refunded_amount"], 2),
    }


def request_human_approval(order_id: str, amount: float, reason: str) -> bool:
    """Placeholder approval gate. Replace with a real human-in-the-loop workflow
    (e.g. push to an agent approval queue and wait for a response) - blocking on
    stdin is only reasonable for this demo."""
    reply = input(
        f"\n[approval needed] Refund ${amount:.2f} on {order_id} - reason: {reason!r}. Approve? [y/N] "
    )
    return reply.strip().lower() == "y"


def issue_refund(order_id: str, amount: float, reason: str) -> dict:
    order = ORDERS.get(order_id)
    if order is None:
        raise ToolError(f"No order found with id '{order_id}'.")
    if amount <= 0:
        raise ToolError("Refund amount must be greater than zero.")
    refundable = round(order["total"] - order["refunded_amount"], 2)
    if amount > refundable:
        raise ToolError(
            f"Refund amount ${amount:.2f} exceeds the refundable balance of ${refundable:.2f} on {order_id}."
        )
    if not request_human_approval(order_id, amount, reason):
        raise ToolError("Refund was declined by the approving agent.")

    # In production this is where you'd call your payment processor's refund API.
    order["refunded_amount"] = round(order["refunded_amount"] + amount, 2)
    return {
        "refund_id": f"re_{uuid.uuid4().hex[:12]}",
        "order_id": order_id,
        "amount": amount,
        "currency": order["currency"],
        "status": "succeeded",
    }


def execute_tool(name: str, tool_input: dict) -> tuple[str, bool]:
    """Runs a tool call and returns (content_string, is_error)."""
    try:
        if name == "lookup_order":
            return json.dumps(lookup_order(tool_input["order_id"])), False
        if name == "issue_refund":
            return json.dumps(
                issue_refund(tool_input["order_id"], tool_input["amount"], tool_input["reason"])
            ), False
        return f"Unknown tool: {name}", True
    except ToolError as e:
        return str(e), True


# --------------------------------------------------------------------------
# Tool definitions
# --------------------------------------------------------------------------

TOOLS = [
    {
        "name": "lookup_order",
        "description": (
            "Look up an order by its order ID. Returns items, total, status, and how "
            "much has already been refunded. Always call this before discussing an "
            "order's details or refund eligibility - never guess."
        ),
        "strict": True,
        "input_schema": {
            "type": "object",
            "properties": {
                "order_id": {"type": "string", "description": "The order ID, e.g. 'ORD-1001'."},
            },
            "required": ["order_id"],
            "additionalProperties": False,
        },
    },
    {
        "name": "issue_refund",
        "description": (
            "Issue a refund for an order. Requires a human approval step and will fail "
            "if the amount exceeds the order's refundable balance. Only call this after "
            "you have looked up the order and confirmed the order ID, amount, and reason "
            "with the customer."
        ),
        "strict": True,
        "input_schema": {
            "type": "object",
            "properties": {
                "order_id": {"type": "string"},
                "amount": {
                    "type": "number",
                    "description": "Refund amount in the order's currency; must not exceed the refundable balance.",
                },
                "reason": {"type": "string", "description": "Short reason for the refund."},
            },
            "required": ["order_id", "amount", "reason"],
            "additionalProperties": False,
        },
    },
]

SYSTEM_PROMPT = (
    "You are a customer support agent for an online store. "
    "Use lookup_order to check any order before discussing it - never state order details "
    "you haven't looked up. Before calling issue_refund, confirm the order ID, exact "
    "refund amount, and reason with the customer. Refunds go through a human approval "
    "step and can be declined or fail (e.g. amount too high, order not found); when that "
    "happens, tell the customer plainly what happened and what they can do next."
)


# --------------------------------------------------------------------------
# Agentic loop
# --------------------------------------------------------------------------

def run_agent_turn(messages: list) -> str:
    """Drives tool-use rounds for a single user turn, mutating `messages` in place
    with every assistant/tool-result step, and returns Claude's final text reply."""
    while True:
        try:
            response = client.messages.create(
                model=MODEL,
                max_tokens=2000,
                system=SYSTEM_PROMPT,
                tools=TOOLS,
                messages=messages,
            )
        except anthropic.RateLimitError as e:
            retry_after = int(e.response.headers.get("retry-after", "5"))
            print(f"[rate limited - retrying in {retry_after}s]")
            time.sleep(retry_after)
            continue
        except anthropic.APIConnectionError:
            print("[connection error - retrying]")
            time.sleep(2)
            continue
        except anthropic.APIStatusError as e:
            if e.status_code >= 500:
                print(f"[server error {e.status_code} - retrying]")
                time.sleep(2)
                continue
            raise

        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason == "refusal":
            return "Sorry, I'm not able to help with that."

        if response.stop_reason != "tool_use":
            return next((b.text for b in response.content if b.type == "text"), "")

        # Execute every tool_use block from this turn, then return all results
        # together in a single user message (required for parallel tool calls).
        tool_results = []
        for block in response.content:
            if block.type != "tool_use":
                continue
            content, is_error = execute_tool(block.name, block.input)
            tool_results.append(
                {
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": content,
                    "is_error": is_error,
                }
            )
        messages.append({"role": "user", "content": tool_results})
        # loop back around so Claude can see the tool results and continue


def main():
    messages: list = []
    print("Support bot ready (orders ORD-1001, ORD-1002 in the demo data). Type 'quit' to exit.")
    while True:
        user_input = input("\nYou: ").strip()
        if user_input.lower() in ("quit", "exit"):
            break
        if not user_input:
            continue
        messages.append({"role": "user", "content": user_input})
        reply = run_agent_turn(messages)
        print(f"Bot: {reply}")


if __name__ == "__main__":
    main()
