Created `ticket_search_tool.py` (Python, `anthropic` SDK) plus `requirements.txt`.

**Design choice:** a single `query: str` parameter that gets passed straight through to your endpoint, rather than structured fields (`status`, `team`, `created_after`, ...) that get assembled into the DSL client-side. Your endpoint already speaks a full boolean query language (AND/OR, parens, comparison operators) — trying to model that as separate typed parameters would either lose expressiveness or just reimplement a query-string builder. Instead, the tool description teaches Claude the DSL directly (fields, operators, an example), so it writes queries like `status:open AND team:platform AND created:>2026-01-01` itself.

Key points:
- Uses `@beta_tool` + `client.beta.messages.tool_runner(...)` (the recommended way to wire a Python function up as an agent tool — schema is auto-generated from the signature/docstring, no manual loop needed).
- `search_tickets` calls your endpoint over HTTP (`httpx2`, not `httpx` — that's what the 1.x SDK is built on) and returns a compact text summary so Claude can reason over results without wasting tokens on raw JSON.
- Errors (bad query syntax, auth failure, network issues) come back as a descriptive string instead of raising, so Claude sees the failure and can retry/adjust rather than the whole turn crashing.
- Model defaults to `claude-opus-5` per current guidance.

**To wire it up for real**, set:
```
TICKETS_API_BASE_URL=https://your-ticket-system.example.com
TICKETS_API_TOKEN=<token>
```
and adjust the request shape (path, param names, auth header) and the response-field names (`id`/`title`/`status`/`team`/`assignee`/`created`) to match your actual API — I made reasonable guesses there since I don't have the real spec. Once that's fixed, `python ticket_search_tool.py` runs a sample query end to end.

"""Tool definition that lets a Claude-based agent search tickets via the
ticket system's search endpoint (query DSL like:
  status:open AND team:platform AND created:>2026-01-01
).

Assumptions (adjust to match the real API):
  - Search endpoint: GET {TICKETS_API_BASE_URL}/api/search?q=<query>&limit=<n>
  - Auth: Bearer token in TICKETS_API_TOKEN
  - Response JSON: {"results": [{"id", "title", "status", "team",
    "assignee", "created"}, ...]}
"""

import os

import httpx2 as httpx  # anthropic 1.x is built on httpx2, not httpx
from anthropic import Anthropic, beta_tool

TICKETS_API_BASE_URL = os.environ["TICKETS_API_BASE_URL"]
TICKETS_API_TOKEN = os.environ["TICKETS_API_TOKEN"]


@beta_tool
def search_tickets(query: str, limit: int = 25) -> str:
    """Search tickets using the ticket system's query syntax.

    The query is a single string combining filters with AND / OR (AND has
    higher precedence; use parentheses to override it). Supported fields:
      - status:<value>       e.g. status:open, status:closed, status:in_progress
      - team:<value>         e.g. team:platform
      - assignee:<value>     e.g. assignee:jdoe
      - priority:<value>     e.g. priority:high
      - label:<value>        ticket labels/tags
      - created:<op><date>   ISO 8601 date (YYYY-MM-DD), <op> is one of
                              >, >=, <, <=, = -- e.g. created:>2026-01-01
      - updated:<op><date>   same comparison operators, on last-updated time

    Example: "status:open AND (team:platform OR team:infra) AND created:>2026-01-01"

    Call this when the user asks to find, list, count, or look up tickets
    matching some criteria. Do not call it to create, update, or comment on
    tickets -- it is read-only search.

    Args:
        query: The search query string in the ticket system's DSL, e.g.
            "status:open AND team:platform AND created:>2026-01-01".
        limit: Maximum number of tickets to return (1-100). Defaults to 25.
    """
    limit = max(1, min(limit, 100))

    try:
        response = httpx.get(
            f"{TICKETS_API_BASE_URL}/api/search",
            params={"q": query, "limit": limit},
            headers={"Authorization": f"Bearer {TICKETS_API_TOKEN}"},
            timeout=30.0,
        )
        response.raise_for_status()
    except httpx.HTTPStatusError as e:
        return (
            f"Ticket search failed ({e.response.status_code}): "
            f"{e.response.text[:500]}. Check the query syntax and try again."
        )
    except httpx.HTTPError as e:
        return f"Ticket search request failed: {e}"

    data = response.json()
    tickets = data.get("results", data.get("tickets", []))
    if not tickets:
        return "No tickets matched the query."

    lines = [
        f"- [{t.get('id')}] {t.get('title', '(no title)')} "
        f"(status={t.get('status')}, team={t.get('team')}, "
        f"assignee={t.get('assignee', 'unassigned')}, created={t.get('created')})"
        for t in tickets[:limit]
    ]
    return "\n".join(lines)


def run_agent(user_message: str) -> None:
    """Run one turn of a tool-using agent that can search tickets."""
    client = Anthropic()

    runner = client.beta.messages.tool_runner(
        model="claude-opus-5",
        max_tokens=16000,
        tools=[search_tickets],
        messages=[{"role": "user", "content": user_message}],
    )
    for message in runner:
        for block in message.content:
            if block.type == "text":
                print(block.text)


if __name__ == "__main__":
    run_agent("Find open tickets owned by the platform team created after Jan 1 2026.")
