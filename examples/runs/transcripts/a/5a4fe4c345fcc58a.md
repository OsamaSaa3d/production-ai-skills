**Assumptions** (no existing repo/tracker was specified, so I made it pluggable rather than guessing wrong): plain Python, `IssueStore` backed by a local JSON file standing in for a real tracker, and a configurable team registry rather than a hardcoded org chart.

**Pipeline** (`bug_triage/agent.py`):
1. **Parse** the report into title/body.
2. **Retrieve candidates** (`retrieval.py`) — a dependency-free TF-IDF + cosine similarity search over the existing issue store. This is cheap lexical pre-filtering, not the duplicate verdict itself.
3. **Classify** (`llm_client.py`) — one Claude call, forced tool-use (`submit_triage`), given the report, the top-K candidates, the severity rubric, and the team list from `config/teams.json`. Returns duplicate verdict + reason, severity + reason, team + reason, and labels.
4. **Apply guardrails + write back** (`agent.py`): a duplicate verdict below a confidence threshold (default 0.6) is downgraded to "not a duplicate" rather than silently merging two different bugs; a team name the model invents that isn't in the config falls back to "Triage / Unassigned"; a duplicate target that doesn't exist in the store is filed fresh instead of dropped.

**Why two-stage duplicate detection**: lexical retrieval narrows a large store to a handful of plausible matches cheaply (no embeddings API needed), then the model — which can reason about paraphrases and root cause vs. symptom — makes the actual duplicate call and explains it.
